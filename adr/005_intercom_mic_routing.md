# 005. 録音はインカムのマイクから行い、経路は「音声認識」として張る

- **日付**: 2026-09-22（最終更新 2026-09-27）
- **ステータス**: 採用

## 背景

走行中の録音が、人が聞いても聞き取れないほどノイズまみれだった。
後処理のノイズ除去は63パターン試して全滅し、AWS にマネージドサービスも無かった。
一方で、同じ端末・同じインカムで Google レコーダーは綺麗に録れていた。

録り方を測り直すと、本アプリはインカムのマイクを使えておらず、ヘルメットの外にある Pixel の本体マイクで録っていた。
インカムのノイズ除去（CVC）は一度も経路に入っていなかった。

気づけなかった理由は `expo-audio` 1.1.1 の `setInput()` にある。
`setCommunicationDevice()` に入力デバイスを渡しているが、公式仕様は出力（sink）しか受け付けない。
`false` が返るのに戻り値を捨てているため、例外もエラーも出ず、画面は「Bluetooth」を選んだと表示していた。

## 選択肢

### 経路を誰が張るか

| 案 | 判断 |
|---|---|
| A. `setInput()` を呼ばず `MODE_IN_COMMUNICATION` だけで乗せる | 却下。実機で3通り試して全て本体マイクだった |
| B. `expo-audio` に patch-package を当てる | 却下。`setInput()` だけでは足りず（モード管理とリスナーも要る）、`node_modules` へのパッチを維持し続けることになる |
| C. `expo-audio` に PR を出す / fork する | 却下。マージされても SDK 54 には来ない |
| D. 録音まるごと自前のネイティブで書く | 却下。ファイル管理・権限・ライフサイクルまで抱える。経路さえ張れば録音は `expo-audio` で足りる |
| **E. 経路だけ自前モジュール（`modules/bt-audio-route/`）、録音は `expo-audio`** | 採用 |

### 経路をどう張るか

インカムのボタンを押すと、インカムは AT+BVRA=1（音声認識を始めて）を送り、返事を約5秒待つ。その間は codec の交渉に応じない。

| 案 | 判断 |
|---|---|
| F. 仮想通話として張る（`setCommunicationDevice()` に SCO の出力を渡す） | 却下。ボタンで起動した直後に張れない（返事待ちの間）。通話中のボタンは「電話を切る」（AT+CHUP）になり、Android は仮想通話を終わらせるだけでアプリに知らせず、要求が残っているので張り直される。ボタン再押しで終える [003](003_end_of_speech_detection.md) と両立しない |
| G. 仮想通話のまま、確立待ちを5秒以上に延ばす | 却下。録音開始が5秒遅れ、再押しは「電話を切る」のまま |
| **H. `BluetoothHeadset.startVoiceRecognition()` で音声認識として張る** | 採用。ボタンの要求に正式に返事をするので待ちが解け、Bluetooth スタック自身が SCO を張る。仮想通話を使わないので、再押しは AT+BVRA=0 として届き、SCO が切れる |

## 決定

経路は自前モジュールが `startVoiceRecognition()` で張り、録音は `expo-audio` が行う。

- ⚠️ `setCommunicationDevice()` は併用しない。併用すると、インカムが経路を切った後に AudioService が仮想通話で張り直す。
- ⚠️ `setAudioModeAsync({ shouldRouteThroughEarpiece })` は使わない。`expo-audio` がそこで `setSpeakerphoneOn()` を呼び、公式手順が禁じる操作になる。
- 再押しは SCO が切れたことで検知する（HFP の状態通知と 0.2秒ごとの確認の両方。通知の受信には `RECEIVER_EXPORTED` が要る。送り主が Bluetooth アプリで uid が違うため）。
- 確立の待ちは最大2秒で打ち切る（実測は 217〜500ms）。
- 張れなかったときは本体マイクで録って続行する（走行中に黙るのが最も困る）。インカム未接続なら何も出さず、接続しているのに張れないときは画面とログに残す。どちらのマイクで録ったかは必ず記録する。

## 影響

- ネイティブコードが増えるので、`android/` の再ビルドが要る。
- `BLUETOOTH_CONNECT` の宣言と実行時の要求が要る（Android 12 以降）。特権 API は使わない。
- ⚠️ 押下から約5秒以内に返事をする必要がある。アプリが起動していない状態からの押下でも、押下から返事まで 1.64秒で間に合った。
- ⚠️ 検証は Pixel 8a（SDK 36）とインカム1台だけ。SCO を AudioService が管理する構成の端末では「併用しないから張り直されない」前提が崩れうるので、端末を変えたら記録で確かめ直す。
- `voice_communication`（端末側のノイズ除去とエコーキャンセル）を捨ててよいかは、インカムの CVC で足りるかを走行で測ってから決める。
- ノイズ除去の比較は、本体マイク同士で行ったものなのでやり直しになる。
