# 002. 応答後は設定で選んだアプリを LAUNCHER インテントで開いて戻る

- **日付**: 2026-08-21（最終更新 2026-09-27）
- **ステータス**: 採用

## 背景

インカムのボタンで起動すると、本アプリは新しいタスクとして前面に出るので、ナビ中のマップが引っ込む（[001](001_handsfree_launch_mechanism.md)）。
走行中は手で戻せないので、戻す操作まで自動でなければハンズフリーが完結しない。
利用者の希望は「回答が届いた時点で戻り、読み上げは背面で続く」こと。

## 選択肢

| 案 | 判断 |
|---|---|
| A. `moveTaskToBack()` で自アプリを背面に退ける | 却下。実機（Pixel 8a）でホーム画面に落ち、マップは最小化されたままだった。自分のタスクを下げるだけで、次に何を前面に出すかは決めないため |
| B. マップのタスクを `AppTask#moveToFront()` で上げる | 却下。`getAppTasks()` は自分のタスクしか返さず、マップのタスクを取れない |
| C. 直前に前面だったアプリを記録して戻す | 却下。他アプリの前面判定は塞がれている。`UsageStatsManager` は特別な権限が要り、重い |
| D. 戻り先を設定で持ち、`getLaunchIntentForPackage()` で開く | 採用。LAUNCHER インテントは既存のタスクを再開する（タスク ID が変わらないことを実機で確認）ので、案内中のルートは壊れない |
| E. 「送信できた時点」で戻す（前倒し） | 却下。背面に回ると Android がプロセスをキャッシュに落として JS を凍結し、ポーリングが止まって回答が来なかった。背面で待つにはフォアグラウンドサービスが要り、薄いクライアントの方針に反する |

## 決定

- 戻り先は設定画面でインストール済みアプリから1つ選ぶ。既定は「戻らない」。
- 戻すのはハンズフリー起動で始まった一往復だけ（画面から操作したときは戻さない）。
- 戻すのは回答が届いた時点。読み上げの完了は待たない。
- 背面で読み上げを続けるため、`shouldPlayInBackground: true` と `interruptionMode: "mixWithOthers"` の両方を設定する（マップが案内音声のためにオーディオフォーカスを取ると、後者が無ければ再生が止まる）。
- 背面に回った後の失敗は、端末内蔵の TTS で読み上げて知らせる（画面は見えない）。

## 影響

- 設定が1つ増える。戻り先を知る手段が他に無いので受け入れる。
- ⚠️ Android 11 以降は `<queries>` の宣言が無いとアプリ一覧が黙って空になる。`QUERY_ALL_PACKAGES` は Play の審査対象なので使わない。
- 既定が「戻らない」なので、未設定のときは画面の「設定」リンクにその旨を出す（黙って何もしないと壊れているように見える）。
