# 003. 終話はインカムのボタン再押しと録音の上限で決める

- **日付**: 2026-09-09（最終更新 2026-09-27）
- **ステータス**: 採用

## 背景

US-2.04 の「終わり」、つまり話し終えたことをどう判定するか。
停車中は音量ベースの無音検知（VAD）で成立していたが、走行中の実測で成立しないと分かった。

| 事実 | 中身 |
|---|---|
| エンジン始動で音量が飽和する | `metering` が 0 dBFS（`maxAmplitude` 32767）に張り付き、発話しても値が動かない |
| 閾値の調整では直らない | 飽和した値は変化しないので、差が取れない |
| `audioSource` を変えても直らない | 4種を実測し、最良の `voice_communication` もアクセルを開けると 0 dB に達した |
| 原因はエンジン音 | 停車してアイドリングするだけで再現する |

走行中は画面を見られないので、速度によって壊れる仕組みは使えない。

## 選択肢

| 案 | 中身 | 判断 |
|---|---|---|
| A. 音量ベースの VAD を続ける | 閾値・適応閾値・移動平均を詰める | 却下。飽和は情報が消えているので、後段の工夫では原理的に直らない |
| B. オンデバイス音声認識に判定させる | 声らしさで判定する | 却下。同じ割れた音が入るので成立が未知で、成立すれば Backend の Transcribe 経路を捨てることになる。C が成立したので理由が無い |
| **C. インカムのボタンをもう一度押して終える** | 録音中の押下を「話し終えた」とみなす | 採用。音を見ないので騒音の影響を受けない。押すのはインカムなので要件（スマホに触れない）を満たし、起動と同じボタンで一貫する |
| **D. 録音の上限で切る** | `maxRecordingMs` に達したら送る | 併用。押し忘れ・押し損ねの受け皿 |

## 決定

C と D を併用する。どちらかが必ず効くので、質問は失われない。

```
録音開始
  ├─ ボタンを押した      → その時点で送信（C）
  └─ 押されないまま N秒  → 自動で送信（D）
```

音量ベースの VAD と、それに依存する騒音ガード（騒音だけの録音を捨てる仕組み）は持たない。
走行中は騒音ガードが常に成立して全ての録音を捨ててしまい、守りとして働かないため。

再押しの届き方は、録音に使うマイクで変わる（[005](005_intercom_mic_routing.md)）。

| 録音中のマイク | 再押しの届き方 |
|---|---|
| インカム（経路を音声認識として張る） | インカムが AT+BVRA=0 を送り、SCO が切れる。Android はアプリに Intent を送らないので、経路が切れたことを検知する（`watchIntercomEnded`） |
| 本体マイク（インカム未接続・経路の失敗） | 録音中に `VOICE_COMMAND` が届く（実機で確認） |

## 影響

- 変更は App の中で閉じる。Backend（`POST /ask-audio` 以降）は変えない。
- ⚠️ `VOICE_COMMAND` の意味が録音中か否かで変わる。録音中の押下は、録音開始の処理より前に分岐させる。
- 1秒未満の録音は送らない（`MIN_RECORDING_MS`）。ボタンのチャタリングや二重の押下で空の録音を送らないため。録音は続くので質問は失われない。
- `maxRecordingMs` の既定は 20秒。長いと、押さずに待つときにその分待たされる。設定画面から変えられる。
- 録音中は残り秒数を画面で最も大きく出す（押さずに待つかの判断に要る）。
- `audioSource` の既定は `voice_communication`（終話には効かないが、4種でノイズ除去が最も効いた）。
